# ゲーム企画・仕様書：『テラ・フォーミング・パズル（仮）』 (3D版)

## 1. 企画概要
*   **タイトル**: テラ・フォーミング・パズル（Terraforming Puzzle 3D）
*   **ジャンル**: 3Dパズル × 地形変化ローグライク
*   **プラットフォーム**: PC / モバイル
*   **開発環境**: Unity (C#)
*   **グラフィック方針**: Unityのプリミティブ（Cube、Sphereなど）とマテリアルの色分けのみで構成する、シンプルでスタイリッシュなミニマリズムデザイン。

### 1.1. コアコンセプト
**「立体的な盤面を、色と形で作り変えるテラフォーミング」**
3D空間に配置された8×8のグリッド（Cube）に対してエレメントを放ち、不毛な灰色の世界を、カラフルで生命力豊かな世界へと変化させる。

---

## 2. 画面構成とプリミティブ（3D）の割り当て
高価な3Dモデルは一切使わず、Unity標準の形状とマテリアルの色（Color）だけで世界観を表現します。

### 2.1. 盤面（グリッド）の構造
*   **ベース盤面**: 8 × 8 の位置に配置された **Cube（立方体）**。
*   **タイルの表現（マテリアルと高さの変更）**:
    *   状態に応じて、Cubeの色（マテリアル）と「Y軸の高さ（LocalScale.y）」を変化させ、地形の立体感を出します。

| 地形 | 使用するプリミティブ | 色（マテリアル） | 高さ（Scale.y）のイメージ |
| :--- | :--- | :--- | :--- |
| **【空き地/荒地】** | Cube | 灰色 (Gray) | 0.2（平らで低い） |
| **【水】** | Cube | 青色 (Blue) | 0.1（少し沈んでいる） |
| **【土】** | Cube | 茶色 (Brown) | 0.4（少し盛り上がっている） |
| **【火】** | Cube | 赤色 (Red) | 0.6（燃え上がっている） |
| **【泥】** | Cube | 濃い茶色 (Dark Brown) | 0.3（湿っている） |
| **【肥沃な大地】** | Cube | 鮮やかな緑 (Green) | 0.5（豊かな大地） |
| **【砂漠】** | Cube | 黄土色/薄黄 (Yellow) | 0.2（乾燥している） |

### 2.2. 特殊エフェクト（視覚的演出）
*   **植物が芽吹いた表現**: 【肥沃な大地】が完成した際、Cubeの上に小さな **Sphere（球体：黄緑）** や **Cylinder（円柱：緑）** を「木」や「草」に見立てて上にポンと生成（Instantiate）します。
*   **選択中カーソル**: プレイヤーが現在狙っているマスの上に、半透明の白い **Cube** を浮かせて点滅させます。

### 2.3. カメラワーク
*   盤面を斜め上から見下ろす **クォータービュー（アイソメトリック視点）**。
*   Cameraの Projection を `Orthographic`（平行投影）に設定。

## 2.4. 具体的なゲームルールと進行詳細

プレイヤーが1ターンに体験するアクションのルールと、裏側で動く計算の順序（タイムライン）の詳細です。

### 1. 手札の選択と制限
*   プレイヤーの手札スロットは最大3枚。
*   各カード（エレメント）には、そのステージ内で「使える総数」が割り振られています（例：【水】カードの残り枚数：5枚）。
*   手札を1枚使うと、そのエレメントの残り総数から1枚消費され、新しいカードがランダムにスロットへ補充されます。すべての総数が0になり、手札も盤面に置けなくなると「手札切れ」でゲームオーバー（またはその時点のスコアで判定）となります。

### 2. プレイヤーのターン：配置と「即時コンボ」
プレイヤーが盤面の「空き地（灰色）」または「対象となるマス」にエレメントを配置した瞬間、以下の順序でルールが適用されます。

*   **ステップ①：上書き・設置**
    指定したマスにエレメントが設置され、見た目（色・高さ）が変化します。
*   **ステップ②：隣接4マスのスキャン**
    設置されたマスの「上・下・左・右」に隣接するマスをプログラムが確認します。
*   **ステップ③：コンボ（地形変化）の実行**
    隣接するマスとの間で、以下の**「3大コンボルール」**が1度だけ実行されます。

#### 【コンボ1：緑化（スコア獲得）】
*   **条件**: 【土】マスの隣に【水】を置く（またはその逆）。
*   **結果**: 
    1. 【土】マスが潤い、**【泥（濃い茶色）】**に変化する。
    2. すでに【泥】になっているマスの隣に、さらに【水】を置くと、その泥が**【肥沃な大地（緑）】**に最終進化する。
    3. 【肥沃な大地】になった瞬間、**「基本スコア＋100点」**が加算され、マスの真上にプリミティブの「木（緑の円柱）」がポップアップする。
*   **性質**: 【肥沃な大地】および【泥】のマスは、もう上から他のプレイヤーエレメントを配置することはできません（砂漠などの環境変化による上書きを除く）。

#### 【コンボ2：消火と冷却（お邪魔排除）】
*   **条件**: 最初からステージに配置されている（、またはギミックで発生した）炎上する**【火（赤）】**マスの隣、または真上に【水】を置く。
*   **結果**: 
    *   【火】と【水】がお互いを打ち消し合い、両方のマスが何もない**【空き地（灰色）】**にリセットされる。
    *   邪魔な火を消し止めたボーナスとして**「環境浄化スコア＋50点」**を獲得する。

#### 【コンボ3：砂漠化（プレイヤーへのペナルティ）】
*   **条件**: **【砂漠（黄土色）】**のマスは、プレイヤーが直接置くことはできません。これは「環境（敵）」の要素です。
*   **結果**: 砂漠化ルールは後述の「環境フェーズ」で動きます。

---

### 3. 環境フェーズ：敵（自然の脅威）のターン
プレイヤーが1枚エレメントを配置し終えると、1ターンが消費され、自動的に「環境フェーズ」へ移行します。

*   **ルール①：砂漠の侵食**
    *   盤面に存在するすべての【砂漠（黄土色）】マスは、周囲4マスに【肥沃な大地（緑）】または【土（茶色）】がある場合、1ターンごとに**20%の確率でそのマスを【砂漠】へ上書き（侵食）**します。
    *   せっかく作った緑の大地も、近くの砂漠を【水】で食い止めたり（※水は砂漠をただの土に戻す特性を持つ）、壁を作って隔離しないと、徐々に砂漠に飲み込まれてスコアが減少（緑が消えるため）してしまいます。
*   **ルール②：火災の延焼**
    *   盤面にある【火】は、隣に【土（茶色）】や【肥沃な大地（緑）】などの燃える素材がある場合、2ターンに1回のペースで隣のマスへ燃え広がります。放置すると盤面が火の海になります。

---

### 4. 勝敗条件の確定

*   **クリア（勝利）条件**:
    *   画面左上の「残りターン数（例：20ターン）」が0になる前に、画面右上の「目標スコア（例：3,000点）」に到達する。
*   **ゲームオーバー（敗北）条件**:
    *   目標スコアに届かないまま「残りターン数」が0になる。
    *   使えるエレメントの残り総数がすべて0になり、手札が尽きる。
    *   盤面がすべて【砂漠】または【火】で埋め尽くされ、プレイヤーが手を下せなくなる。

## 3. 画面UI構成（Screen Layout）

Unityの `Canvas (uGUI)` または `UI Toolkit` を使用して構築します。プリミティブのミニマルな世界観に合わせ、UIも白と黒を基調としたフラットデザインにします。

### 3.1. UI要素一覧
*   **ヘッダー（情報表示）**:
    *   `Turn Text`: 残りターン数 / 最大ターン数
    *   `Score Text`: 現在のスコア / クリア目標スコア（ゲージ表示を合わせると視覚的にわかりやすい）
*   **フッター（操作エリア）**:
    *   `Hand Slots (x3)`: 次に配置できるエレメントカード。選択中のスロットは枠線がハイライトされる。
    *   `System Buttons`: 「リセット（最初からやり直す）」「タイトルへ戻る」ボタン。

## 4. 開発工程・実装作業見積もり（工数目安）

個人開発（1日2〜3時間の作業）を想定した、最小限の遊べるプロトタイプ（MVP）完成までのスケジュールです。**合計：約2週間（約14日間）**

| フェーズ | 日数 | 作業内容詳細 |
| :--- | :---: | :--- |
| **1. プロジェクト準備 & 画面構成** | 2日 | プロジェクト作成、カメラの配置（Orthographic）、3D盤面（8x8 Cube）の自動生成スクリプト作成、マテリアル（各色）の用意。 |
| **2. マウス入力 & レイキャスト** | 2日 | マウスカーソルの位置から `Physics.Raycast` を飛ばし、接触したCubeの座標（X, Z）を特定する処理。選択中カーソル（半透明Cube）の表示。 |
| **3. データ構造 & 配置システム** | 3日 | `TileData` クラスの定義。手札のUIをクリックし、盤面のCubeをクリックしたらそのマスの `TileType` が変わり、色と高さ（Y軸Scale）が変化する連鎖の土台。 |
| **4. 地形変化（コンボ）ロジック** | 3日 | 今回のコア。配置したマスの「上下左右（4方向）」を配列でスキャンし、属性の変化（土＋水＝泥など）を計算するアルゴリズムの実装。肥沃な大地の上にSphere（木）を生成する演出。 |
| **5. ゲームループ & UI接続** | 2日 | ターン減少、スコア加算、目標達成時の「Clear!」画面、ターン切れ時の「Game Over」画面の実装とUIのデータ連動。 |
| **6. バグ調整 & 仕上げ** | 2日 | 隣接チェックが盤面の端（インデックス外エラー）で落ちないかのチェック、砂漠の自動侵食ギミックの微調整、全体のテンポ調整。 |

## 5. 今後の拡張案（優先度順ロードマップ）

プロトタイプが完成した後に、ゲームとしてのクオリティやリプレイ性を高めるための拡張アイデアです。実装のしやすさと面白さのコスパ順に並べています。

### 🌟 優先度：高（ゲームの基礎的な面白さを強化）
1.  **ステージ制とミッションの導入**
    *   「すべての火を消せ」「15ターン以内に肥沃な大地を20マス作れ」など、ステージごとに異なるクリア条件を設定。
2.  **演出の強化（Tweenアニメーション）**
    *   マスの色や高さが変わる際、一瞬で変わるのではなく、0.2秒ほどかけて「ニュッと動く」アニメーションをC#コード（`Vector3.Lerp` や `LeanTween` 等）で実装し、触り心地を気持ちよくする。

### 🌟 優先度：中（戦略性とリプレイ性をアップ）
3.  **ローグライク・パワーアップ要素（ステージ間報酬）**
    *   ステージをクリアするごとに、ランダムに提示される3つの特殊能力から1つを選んで自陣を強化できる。
    *   （例：「水タイルの効果範囲が周囲2マスになる」「火を消滅させるとスコア2倍」「毎ターン10%の確率で自動で雨が降る」など）
4.  **連鎖（チェイン）コンボボーナス**
    *   「泥が肥沃な大地に変わった衝撃で、隣の土も泥に変わる」といった、1回の配置で2段階、3段階と連続して地形が変わる連鎖システムと、それに応じた高得点ボーナス。

### 🌟 優先度：低（見た目の豪華さややり込み要素）
5.  **天候・シーズンギミック**
    *   5ターンごとに「豪雨（ランダムに3マスが水になる）」「日照り（水が干からびやすくなる）」などの環境変化イベントが発生する。
6.  **プリミティブの「スキン」機能**
    *   ゲーム内ポイントで、Cubeのデザイン（ネオン風、サイバー風、和風のカラーパレットなど）をアンロックして切り替えられる機能。
